## **2. модуль ```classes.py``` в пакете ```src```**
### ***Классы и объекты ООП***
    Классы не просто хранят данные, но и динамически отслеживают состояние всей системы
    (ведут сквозной подсчет созданных объектов) за счет механизмов инкапсуляции и атрибутов класса.

### 1. Класс Product (Модель товара).
    Отвечает за создание и хранение информации о конкретной торговой единице.
    
* **Тип данных:** Объектный класс (динамическая модель).

#### Атрибуты экземпляра (Свойства объекта):
    - name / str / публичный / — уникальное коммерческое наименование товара.
    - description / str / публичный / — подробное описание характеристик товара.
    - price / float / приватный / — текущая стоимость единицы товара.
    - quantity / int / публичный / — доступный остаток товара на складе.

#### Основной функционал и бизнес-логика:
* **Инкапсуляция цены (Геттер и Сеттер):**
  * Прямой доступ к изменению цены ограничен. Чтение происходит через свойство-геттер `price`.
  * При изменении цены через сеттер выполняется валидация: цена не может быть нулевой или отрицательной.
  * Реализована защита от случайного снижения стоимости: если новая цена ниже текущей, система запрашивает интерактивное подтверждение пользователя в терминале `(y/n)`.

* **Фабричный метод `new_product`:**
  * Позволяет инициализировать объект класса на основе сырых данных из словаря (`dict[str, Any]`), гарантируя безопасное приведение типов данных.
  * **Умное объединение дубликатов:** Если при создании нового товара передан список уже существующих товаров (`products_list`), метод проверяет совпадение по имени (`name`). При обнаружении дубликата:
    1. Суммирует их складские остатки (`quantity`).
    2. Автоматически устанавливает наибольшую цену из двух, используя встроенную логику сеттера.
    3. Вместо создания нового объекта возвращает обновленный существующий.

    2. Класс Category (Модель категории). Выступает в роли контейнера-группировщика для объектов класса Product. Помимо хранения локальных данных, класс выполняет аналитическую функцию — отслеживает глобальное состояние всей торговой системы.
        - #### Свойства объекта (Атрибуты экземпляра):
            - name (строка - str) — название товарной группы (например, «Смартфоны»).
            - description (строка - str) — описание группы товаров.
            - products (список объектов - list) — коллекция экземпляров класса Product, входящих в эту категорию.
        - #### Глобальные свойства (Атрибуты класса / Статические переменные):
            - category_count (целое число - init) — счетчик, фиксирующий общее количество созданных категорий в системе.
            - product_count (целое число - init) — счетчик, фиксирующий суммарное количество уникальных товаров, распределенных по всем категориям.

    Логика работы сквозных счетчиков (Конструктор Category). При инициализации каждого нового объекта категории ```(__init__)``` автоматически срабатывает механизм агрегации данных, основанный на изменении состояния самого класса:
        - Инкремент категорий ```(Category.category_count += 1)```:
            Каждый раз, когда создается новая категория, этот счетчик увеличивается на 1. Переменная связана напрямую с именем класса Category, что позволяет сохранять значение между созданиями разных объектов.
        - Агрегация количества товаров ```(Category.product_count += len(products))```:
            Конструктор принимает на вход список товаров products. Встроенная функция ```len()``` вычисляет количество элементов (товаров) в этом списке. Оператор ```+=``` прибавляет полученное число к общему глобальному счетчику. Таким образом, система в реальном времени знает, сколько всего товаров загружено в магазин.

    ### Магические методы и итераторы

#### Строковое представление объектов (`__str__`)
* **Для класса `Product`**: Возвращает строку в формате: `Название продукта, X руб. Остаток: X шт.`
* **Для класса `Category`**: Возвращает строку в формате: `Название категории, количество продуктов: X шт.` (Суммирует общее количество всех единиц товара на складе для данной категории).
* **Оптимизация**: Геттер `products` переведён на использование метода `__str__` каждого продукта для исключения дублирования логики.

#### Магический метод сложения (`__add__`)
* Добавлен для класса `Product`. Позволяет складывать два товара.
* Возвращает **суммарную стоимость** всех единиц данных товаров на складе (Рассчитывается по формуле: `Цена_А × Количество_А + Цена_Б × Количество_Б`).
* Защищён от сложения с объектами других типов данных (`TypeError`).

#### Вспомогательный класс-итератор `CategoryIterator`
* Позволяет обходить (перебирать) товары конкретной категории в стандартном цикле `for`.
* Реализует методы `__iter__` и `__next__`, поочерёдно возвращая объекты продуктов.

    ### Полиморфизм и Наследование

1. **Иерархия классов и наследование**:
   * Создан базовый класс `Product`, от которого унаследованы два специализированных класса: `Smartphone` (Смартфоны) и `LawnGrass` (Газонная трава).
   * Дочерние классы переиспользуют базовую логику инициализации через `super().__init__()` и добавляют свои уникальные свойства (характеристики устройств и агрономические свойства).

2. **Контроль типов при наполнении категорий**:
   * В метод `Category.add_product()` интегрирована строгая проверка типов на основе функции `isinstance()`.
   * Система разрешает добавлять в категорию только объекты класса `Product` или его прямых наследников (`Smartphone`, `LawnGrass`). Попытка передать объект стороннего типа данных вызовет исключение `TypeError`.

3. **Строгое сложение товаров (Полиморфизм)**:
   * Метод `__add__` базового класса `Product` переработан для обеспечения логической целостности складского учета.
   * Введена проверка `type(self) is not type(other)`. Теперь можно складывать только товары **одинаковых классов**. Сложение `Smartphone` с `LawnGrass` или `Smartphone` с базовым `Product` заблокировано и приводит к генерации ошибки `TypeError`.

     ### Принцип разделения обязанностей и миксины (Задание 16.2)
* **Создан класс-миксин `PrintMixin`**: Реализован механизм автоматического логирования создания объектов. Теперь при инициализации любого товара (`Product`, `Smartphone`, `LawnGrass`) в консоль автоматически выводится информация о созданном объекте через метод `__repr__`.
* **Множественное наследование (MRO)**: Базовый класс `Product` переведен на множественное наследование (`class Product(BaseProduct, PrintMixin)`). Корректно настроена цепочка вызовов `super().__init__()`, что предотвращает падение скрипта на базовом классе `object`.

### Защита данных в Категориях
* **Валидация при добавлении**: Метод `add_product` в классе `Category` теперь строго проверяет тип добавляемого объекта с помощью `isinstance()`. В категорию можно добавить только объект класса `Product` или его наследников (`Smartphone`, `LawnGrass`). Попытка добавить сторонний тип данных (например, строку) вызовет исключение `TypeError`.

### Новая функциональность: Обработка исключений и валидация
* В архитектуру проекта были внедрены механизмы защитного программирования. Основная цель изменений — обеспечение целостности данных на этапе инициализации объектов и предотвращение аварийного завершения работы приложения при математических операциях.

## Тестирование

В проекте используется фреймворк `pytest` для проверки корректности работы функций и обработки ошибок.

### Запуск тестов
Команда выводит информацию в консоль, автоматически запускает все тесты в модулях (во всем проекте) с помощью фреймворка pytest внутри изолированного виртуального окружения Poetry.
```
poetry run pytest
```
Команда выводит информацию в консоль, автоматически запускает тесты в указанном модуле ```tests``` - папка с модулем теста, ```test_decorators.py``` - название модуля тестов
```
pytest tests/test_decorators.py
```
Команда выводит описание ошибки и информацию в консоль, автоматически запускает тесты в указанном модуле
```
pytest -s tests/test_decorators.py
```

### Анализ покрытия кода (Coverage)
Посмотреть, насколько полно код покрыт тестами, используйте `pytest-cov`:
```
poetry run pytest --cov=src
```
Команда автоматически запускает все тесты в проекте (из папки tests) и выводит в консоль сводную таблицу с процентом покрытия кода для модулей внутри директории ```src```
```
pytest --cov=src tests/
```
Команда автоматически запускает все тесты в проекте (из папки tests) и генерирует детальный интерактивный HTML-отчет с процентом покрытия кода для модулей внутри директории ```src```
```
pytest --cov=src --cov-report=html tests/
```
